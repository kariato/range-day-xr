# Blender environment sources

`standard.blend` is the original indoor-range environment authored in Blender 4.5.13 LTS. It includes ten 1.8 metre lanes, acoustic booths, oak equipment shelves, target rails and hangers, overhead baffles, concrete, rubber backstop, ventilation ducts, LED fixtures, floor distance markings, observation glazing and a rear access door. Its procedural and CC0 concrete/gravel PBR tiles are packed into the source. Static fixture/sun visibility, light falloff and ambient occlusion are baked into active vertex colours; this is not a full indirect-light bake.

Open the source in Blender, edit and save, then export:

```sh
BLENDER_BIN=/path/to/blender npm run assets
```

The exporter preserves active vertex colours and packed textures and omits the source's preview lights/camera. These lights help inspect the source in Blender; runtime uses shared game lighting and emissive fixture materials. Normal game builds use the included GLB and need no Blender installation.

`tools/model_indoor_range.py` is the original reproducible authoring script. Running it explicitly overwrites the indoor source and export. Normal export preserves manual source edits. `tools/generate-scenes.mjs` keeps authored scenes and only rebuilds remaining blockouts. The outdoor course, qualification house and warehouse have corresponding editable `.blend` sources as well. Their art passes are generated by `tools/model_training_environments.py` from the preserved gameplay layouts in `assets/blockouts/` and packed indoor materials. The hub is the remaining blockout.

Use metres and +Y-up glTF export. The loader reads `COL_` meshes as hidden Rapier box colliders, `NAV_` meshes as hidden pathfinding geometry, and `SPAWN_dummy_*` empties as spawn points. Preserve collider/navmesh geometry and custom properties in exports. Runtime static meshes merge by material; keep materials shared and include the same vertex attributes on meshes sharing a material. Dynamic targets remain game-owned; their hanger/trolley geometry follows target retrieval.

The environment is an approximate artist interpretation for a game, not manufacturer or engineering data. Ten to twelve shared materials, 256–512 px textures and simplified detail keep the environment exports small. Baked vertex lighting costs no real-time shadow maps. Quest hardware performance and comfort still need device testing.


## Other environments

- `runthrough.blend`: compacted gravel exercise corridor, field grass, earth berms, static tree models, fence wire, station signage and ready-area benches. The original course obstacles and collision positions remain.
- `qualification.blend`: textured modular training walls, blue door-opening frames, room plaques, ceiling, LED fixtures, utility panels and conduit. All six room triggers, opening widths and the return circuit remain game-owned and unchanged.
- `warehouse.blend`: galvanized shelving and blue uprights, timber cases, loading-dock roller-door slats and protective posts, overhead fixtures and ventilation. The original rack collision volumes, navigation mesh and enemy spawn markers remain.

The original compact layout GLBs are in `assets/blockouts/` solely as reproducible authoring seeds. Playing uses the exported art passes in `public/models/`. Each art pass uses shared materials, packed procedural/CC0 textures and baked vertex lighting/AO. This is game art based on plausible range features, not a measured replica or photogrammetry survey.


## Quest 2 asset profile

`src/rendering/budgets.json` defines project limits; `npm run check:environments` checks the shipped GLBs and runs in deployment CI. Environment assets must stay below 90,000 triangles, 16 visible materials, 512 px textures, 8 MiB decoded texture memory (RGBA8 plus full mip chains), and 8 MiB per GLB. Blended transparency, double-sided materials and exported real-time light objects are rejected. These are conservative project limits, not universal Meta hardware guarantees. The generated measurements are in `docs/environment-budgets.json`.

Material detail comes from packed albedo, normal and roughness maps; no displacement/tessellation, screen-space effects, alpha-blended foliage, realtime shadow maps or new custom shaders are used. Smooth normals and simplified sign curves improve silhouettes while reducing polygons. Offline Blender vertex lighting evaluates fixture visibility and falloff for interiors and static sun visibility outdoors. The source retains preview lighting, which is excluded from exports.

[Concrete034 and Gravel023 texture credits and preparation](textures/environment/LICENSE.md). The optimized source PNGs are included; rebuilding does not require a texture CDN. `tools/prepare_environment_textures.py` can reproduce them from the recorded 1K-JPG archives; it reduces resolution and applies a neutral/cool concrete tint and warm gravel tint for the game's exposure. Photo source maps do not add geometric displacement. The normal/roughness maps are capped at 256 px and albedo at 512 px.
